1. Planteamiento y Oportunidad

Contexto y Justificación del Proyecto

El Reto Actual

Los usuarios de Biblioteca Central enfrentan dificultades con catálogos tradicionales basados en búsquedas booleanas exactas, lo que incrementa el tiempo de localización y la carga de atención bibliotecaria.

Diagnóstico Inicial: 83.3% participación

La Solución Propuesta

Un agente conversacional inteligente capaz de comprender lenguaje natural coloquial, interpretar necesidades temáticas e interactuar en tiempo real con la API REST del sistema KOHA.

Modelos Metodológicos: SAM y SECI

Hito del Avance

Entrega adelantada de la Fase 1.4 (Prototipo Funcional MVP), demostrando en software real la viabilidad de la arquitectura, conectores y procesamiento de consultas.

Adelanto a la planeación de Octubre
2. Resumen de Ingeniería • Trabajo Realizado

¿Qué se construyó en este periodo?

Desarrollo integral de punta a punta: desde el dataset y fine-tuning hasta el backend y la integración:

1. Backend & Sandbox

Servidor ASP.NET Core (.NET 10) & Mock Koha

Desarrollo del servidor REST desacoplado mediante IKohaService. Ante la demora de TI en liberar accesos OAuth2, se creó un Mock Sandbox RFC de alta fidelidad que replica la API oficial de Koha (/api/v1/biblios), estatus físico y estanterías de Biblioteca Mexicali.

Cero líneas de código a reescribir en producción 100% Desacoplado
2. Curación de Datos

Dataset Especializado UABC (2,956 Muestras)

Generación de un dataset masivo en formato ChatML JSONL. Cubre 80 materias académicas, expansión de siglas comunes (IA, BD, POO, SO), normalización de modismos estudiantiles ("¿Qué onda pa?", "tírame paro") y consultas de reglamentos de préstamo a domicilio.

2,956 registros validados sintéticos 0 Errores de sintaxis
3. Fine-Tuning SLM

Entrenamiento LoRA & Cuantización GGUF

Fine-tuning del modelo Qwen 2.5 (0.5B Instruct) en GPU T4 (Google Colab) con Unsloth y LoRA (r=32, α=64) a lo largo de 550 pasos. Exportación a formato GGUF Q4_K_M (397 MB) para ejecución autónoma sin conexión ni costos de nube.

Inferencia on-premise en CPU < 380 MB RAM
4. Algoritmos de Precisión

Preprocesamiento Léxico y Cero Falsos Positivos

Incorporación de filtros para evitar coincidencias erróneas por palabras genéricas (ej. evitar que "arte moderno" recomiende libros de IA por la palabra "moderno"), con stem matching en español y extracción de intenciones en tiempo real.

Resolución de jerga + derivación morfológica 100% Casos aprobados
3. Blindaje Metodológico

Mitigación de Riesgos Institucionales

Alineación estricta con la Plantilla de Riesgos formalizada en el proyecto (Diapositiva 16):

Riesgo #1 Identificado (Probabilidad: Alta)

Acceso limitado a metadatos KOHA

Causa: Demoras en aprobaciones institucionales, configuración del módulo OAuth2 en Apache por el departamento de TI y políticas de seguridad universitaria.

Acción Correctiva Ejecutada

Entorno Sandbox Controlado

Se implementó un entorno Sandbox (Mock RFC/OpenAPI) que emula con precisión milimétrica la estructura JSON oficial de KOHA REST v1 (/api/v1/biblios), permitiendo validar el agente sin frenar el cronograma de la maestría.

Desacoplamiento Arquitectónico: El paso de Sandbox a Producción se realiza mediante una simple variable de entorno (UseMock=false). Zero Refactor Required
4. Arquitectura del Sistema

Stack Tecnológico y Componentes (.NET 10)

1. Frontend UI

Single Page Application responsiva, con identidad visual UABC (Verde Institucional y Oro), renderizado de tarjetas bibliográficas y feedback conversacional.

2. Backend API

Construido en ASP.NET Core (.NET 10 Minimal API). Alto rendimiento asíncrono, inyección de dependencias limpia y endpoints REST ligeros.

3. SLM Local Entrenado

Qwen 2.5

Qwen 2.5 (0.5B) Fine-Tuned con LoRA sobre consultas de Koha. Inferencia on-premise con LLamaSharp (.NET CPU, <380MB RAM, cero costo de API y 100% privacidad de datos).

4. Conector KOHA

Capa de abstracción (IKohaService) con implementación dual: Mock representativo de Mexicali y cliente OAuth2 real para producción.

⚡ Sin dependencias externas complejas: Compilación nativa, ejecutable portable y arranque inmediato con run.bat. Latencia < 20ms
5. Integración KOHA

Especificación y Flujo OAuth 2.0

Flujo de Autenticación Oficial

Basado en las directrices técnicas del Manual de KOHA API del proyecto:

  • • POST /api/v1/oauth/token
  • • grant_type: "client_credentials"
  • • client_id & client_secret asignados por TI
  • • Header: Authorization: Bearer <token>
Ajuste en Apache:
SetEnvIf Autorización .+ HTTP_AUTHORIZATION=$0
